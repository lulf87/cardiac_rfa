# stage17_controlled_rebuild

This directory contains the canonical stage17 deterministic rebuild for the
comparator-aware four-way study:

- `standard_30W_30s`
- `hpsd_50W_10s`
- `vhpsd_90W_4s_fixed`
- `vhpsd_90W_4s_controlled`

The stage17 branch is intended to support a reduced, assumption-bounded
comparison between a fixed-power and a generic temperature-limited `90 W / 4 s`
comparator. It is not a catheter-specific control-law reconstruction.

## Canonical stage17 configs

- Base case: `configs/baseline_90W_4s_4mm.yaml`
- Four-way protocols: `configs/protocols_stage17_fourway.yaml`
- Selected controller: `configs/controller_selected_stage17.yaml`
- Latency window: `configs/latency_enabled.yaml`
- Phase-prep grid: `configs/phase_prep_stage17_fourway.yaml`
- Wall/cooling/contact scans: `configs/wall_scan_stage17.yaml`,
  `configs/cooling_scan_stage17.yaml`, `configs/contact_scan_stage17.yaml`

The exploratory placeholder controller configs remain in the folder for
provenance, but the canonical stage17 scripts default to
`controller_selected_stage17.yaml`.

## Recommended run order

```bash
cd ~/Projects/cardiac_rfa/simulation/stage17_controlled_rebuild
bash run_fixed_smoke.sh
bash run_controlled_smoke.sh
bash run_all.sh
```

`run_all.sh` executes the canonical four-way workflow:

- fixed `90 W / 4 s` baseline with latency
- controlled `90 W / 4 s` baseline with latency
- four-way protocol comparison
- wall/cooling/contact deterministic scans
- convergence study using the selected controller and latency settings
- four-way phase-preparation sweep

## Scope boundaries

- The model remains planar 2D and reduced-order.
- The controller is generic and surface-adjacent, not device-specific.
- The latency window is a post-pulse thermal continuation, not a separate
  physics model.
- Stage16 uncertainty outputs remain in `simulation/stage16_uq_metrics_ready/`
  and are not regenerated by the stage17 deterministic workflow.
